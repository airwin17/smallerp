# Apache Causeway TinyERP-style Shop ERP

A modular, scalable small-shop ERP system built on **Apache Causeway 3.6.0** (the classic thin-kernel approach, not modern Odoo).

**Goal**: A backend-driven single-page Vue.js frontend that discovers everything dynamically from the Causeway REST API (no hard-coded domain classes or pages).

## Technology Stack

- **Backend**: Apache Causeway 3.6.0 + Spring Boot 3.5.x + JPA/EclipseLink + PostgreSQL (dev = H2)
- **Modules**: base / product / sale / stock / account (composed via mixins)
- **Security**: Spring Security + Causeway bypass modules (AuthorizorBypass / AuthenticatorBypass) for development
- **Database**: H2 in-memory (drop-and-create-tables for dev)
- **Frontend**: Vue.js 3 + PrimeVue + TypeScript (separate repository)
- **Build**: Maven (webapp module)
- **Java**: 21 (must be set via JAVA_HOME/SDKMAN)

## Project Architecture

- **Multi-module Maven** (parent `causeway-app-simpleapp`)
  - `base` – core domain (Partner, User, etc.)
  - `product` – Product, ProductTemplate, ProductCategory
  - `sale` – SaleOrder + lines
  - `stock` – StockLocation, Picking, Move
  - `account` – planned
- **Domain services** live in packages annotated with `@DomainService`
- **RESTful Objects** viewer (`/restful/*`) is the single source of truth
- **Vue.js frontend** (separate repo) consumes the REST API dynamically:
  - List all `@DomainService` actions for the header nav menu
  - Generic object page that loads any object by type+id
  - Dynamic buttons, data tables, toasts, navigation

## How the Frontend Works (Backend-Driven)

1. Vue.js fetches the REST schema and available modules from (`/restful/swagger/private`)
2. It discovers every `@DomainService` action and object
3. The PrimeVue header is built automatically from the REST menuBars endpoint
4. When you click a service or object, the app loads the object via GraphQL-like REST and renders properties/actions dynamically
5. All UI layout (buttons, layouts, actions) comes from Causeway annotations(`@ActionLayout`, `@Action`, `@DomainServiceLayout`, etc.)

No Wicket UI is served to the end user. The original Wicket viewer remains in the codebase for development/debugging only.
